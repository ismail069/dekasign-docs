---
title: "Hosted editor dan session penerima"
description: "Credential editor terpisah dari API key dan identitas penerima."
---

`POST /api/v1/documents/{id}/session` memerlukan `documents:write` dan dokumen privat milik requester yang terikat pada app/key tersebut. `purpose` opsional, 3–120 karakter. `expires_in_seconds` opsional, 60–86400 detik; default 3600 detik. Respons memuat `session_id`, `session_url`, `expires_at`, dan `version` dalam `data`.

`session_url` memuat token rahasia yang dikembalikan sekali. `session_id` adalah ID administratif untuk revocation; ID itu tidak memberikan akses editor. Jangan membangun URL editor dari ID administratif.

Credential opaque pada path `{sessionId}` bersifat rahasia. Jangan masukkan ke analytics/log atau memperlakukannya sebagai key permanen.

- `GET /api/v1/hosted-editor/{sessionId}/commands`: layout, versi, purpose, expiry.
- `GET /api/v1/hosted-editor/{sessionId}/document`: PDF privat.
- `POST /api/v1/hosted-editor/{sessionId}/commands`: `type` SAVE_LAYOUT/COMPLETE, `expectedVersion`, `layout`, idempotency key melalui header atau body `idempotencyKey`.

Layout divalidasi server; konflik versi memerlukan baca ulang. Session expired ditolak. Editor tidak memberi hak menandatangani.

Session terikat pada source/version/digest, issuing key, app, dan requester. Perubahan sumber atau pencabutan kewenangan menolak akses dan replay. **COMPLETE** hanya menyelesaikan persiapan layout; tindakan ini bukan consent, tanda tangan, atau perintah otomatis memulai workflow.

## Cabut akses editor
Gunakan `DELETE /api/v1/documents/{id}/session/{sessionId}` dengan API key ber-scope `documents:write`, header `Idempotency-Key`, serta body berikut:

```json
{"expected_version":1,"reason":"Persiapan dibatalkan oleh pengirim"}
```

Gunakan ID dokumen dan ID administratif sesi dari respons penerbitan. Respons sukses memuat `session_id`, status `REVOKED`, dan versi baru. Konflik versi memerlukan pemeriksaan ulang; mengulang key yang sama tidak menjalankan revocation kedua. Revocation tidak menghapus dokumen atau bukti lama.

## Session penerima
`POST /api/v1/guest/auth` bukan machine-key endpoint. Request OTP memakai `action:"request_otp"`, `email`, `requestId`. Verifikasi memakai `action:"verify_otp"`, konteks sama, `code` enam digit dari kanal resmi.

Jangan mengambil OTP dari log/database/respons development untuk mengaku sebagai penerima. `GET /api/v1/signing/{id}/document` memerlukan session member/guest yang berwenang, bukan Bearer app key. Gunakan UI resmi untuk consent dan penandatanganan.
