## Prinsip routing
Email wajib sebagai baseline approval dan Document Sign. Gunakan email DekaSign atau email organisasi sendiri. WhatsApp hanya tambahan. Untuk default organisasi, DekaSign merupakan fallback bila pengiriman custom email gagal atau kegagalan diketahui sistem. Tidak semua bounce dapat diketahui; accepted bukan delivered/read.

Pilihan **custom email** eksplisit pada Actor mematikan email DekaSign untuk node tersebut, termasuk fallback Actor itu. OTP/security tetap memakai kanal platform tepercaya. Jika ingin fallback default organisasi, jangan memilih override Actor tanpa memahami dampaknya.

## Membuat SMTP
Owner membuka **Notification channels**, memilih **Add channel / SMTP**, memberi nama dan mengisi:
| Field | Contoh non-secret |
|---|---|
| SMTP_HOST | smtp.example.com |
| SMTP_PORT | 465 atau 587 |
| SMTP_SECURE | true untuk 465; false dengan STARTTLS wajib untuk 587 |
| SMTP_USER | notifications@example.com |
| SMTP_PASSWORD | Masukkan secret di form, jangan di dokumentasi |
| SMTP_FROM_NAME | Nama organisasi |
| SMTP_FROM_EMAIL | notifications@example.com |

Simpan, pilih **Test connection**, periksa hasil, lalu aktifkan. Uji SMTP memeriksa koneksi tanpa mengirim pesan. Mengubah konfigurasi menghapus status teruji/aktif. Port 25, TLS yang dimatikan dan host privat tidak didukung.

## Hubungkan WhatsApp tanpa JSON

Owner membuka **Management → Notification channels → Add channel**, lalu memilih **Wati**, **Convia**, atau **Bird**. Siapkan akun provider dan template yang sudah disetujui WhatsApp.

<Steps>
  <Step title="Isi koneksi">
    Beri nama channel, lalu masukkan API key. Wati juga memerlukan nomor pengirim termasuk kode negara dalam format angka, misalnya `6281234567890`. Convia menyediakan Sender ID opsional. Bird memakai API key workspace `bk_`, bukan master key `bm_`; template milik workspace memerlukan nomor pengirim dengan `+`, misalnya `+6281234567890`.
  </Step>
  <Step title="Uji dan ambil daftar template">
    Klik **Test & get templates**. DekaSign memeriksa akses API dan mengambil daftar template dari provider. Jika daftar kosong, buat dan setujui template di provider terlebih dahulu, lalu ulangi. Anda dapat mencari template berdasarkan nama atau bahasa.
  </Step>
  <Step title="Pilih dan tinjau detail">
    Pilih template berstatus **APPROVED**. DekaSign mengambil detail template tersebut, lalu menampilkan ilustrasi pesan, header, body, footer, tombol, dan jumlah parameter wajib. Komponen yang belum didukung menampilkan penjelasan dan mencegah penyimpanan.
  </Step>
  <Step title="Simpan channel terverifikasi">
    Klik **Save verified channel** setelah uji daftar dan detail berhasil. Channel tersimpan dan aktif. API key disimpan terenkripsi dan tidak ditampilkan lagi. Saat mengedit, kosongkan API key untuk memakai key tersimpan atau isi key baru untuk menggantinya, lalu uji ulang.
  </Step>
</Steps>

<Note>
**Test & get templates** hanya membaca katalog dan detail. Respons HTTP 200 memverifikasi akses API; langkah ini tidak mengirim pesan dan tidak membuktikan pesan sampai atau dibaca. Provider mempunyai biaya, kuota, serta persetujuan template sendiri.
</Note>

WatZap belum menyediakan alur template terpandu dalam DekaSign. Halaman provider menjelaskan keterbatasannya. Anda dapat memakai **Custom API** jika API provider yang diperlukan terdokumentasi. Channel lama tetap tersedia; periksa ulang sebelum menggunakannya pada rancangan baru.

## Parameter dan media WhatsApp

Pada Canvas, pilih elemen **Notification**, jenis penerima **Phone number**, lalu channel WhatsApp. Pilih template dan isi setiap parameter wajib dengan **Enter a value** atau **Workflow parameter**. DekaSign menampilkan parameter sesuai template yang dipilih; Anda tidak menulis payload JSON.

| Komponen template | Data yang diisi |
|---|---|
| Header/body dengan placeholder | Teks tetap atau nilai dari parameter workflow. |
| Header image, video, atau document | URL HTTPS publik untuk media yang sesuai. |
| Tombol URL dinamis | Nilai pengganti pada bagian dinamis URL yang telah disetujui provider. |
| Footer/tombol statis | Tetap mengikuti desain template provider. |

URL media harus dapat dibaca provider tanpa login DekaSign. Jangan memakai URL dokumen privat DekaSign, URL jaringan internal, atau menaruh kredensial di URL. Pilih media yang memang diizinkan dibagikan. File privat tidak otomatis diubah menjadi publik. Penerima WhatsApp memerlukan nomor HP yang terdaftar atau dipetakan dalam organisasi.

Jika template berubah, pilih kembali dan tinjau pemetaan parameternya sebelum **Publish**. Template dengan carousel, Flow, autentikasi, atau komponen khusus yang belum didukung tidak dapat dipaksakan menjadi template teks biasa.

## Isi notifikasi email di Canvas

Pada elemen **Notification**, pilih jenis penerima **Email** dan channel pengiriman. Pilih sumber isi:

- **DekaSign default**: gunakan desain pesan bawaan.
- **Message Template**: pilih versi template yang telah dipublikasikan dan sesuai kategori workflow.
- **Manual**: isi subject dan pesan dalam mode **Plain text** atau **HTML**.

Gunakan parameter yang tersedia, lalu periksa **Preview**. HTML tetap melalui validasi keamanan; script tidak didukung. Pilihan isi tidak mengubah penerima atau izin akses dokumen. Lihat [Approval Workflow Engine](/guides/approval-workflows) dan [Email Studio](/guides/email-studio).

## Custom API: Email atau Phone number
Buka **Management → Notification channels** sebagai Owner. Pilih **Email** atau **Phone number** agar elemen Notification pada Canvas menawarkan channel sesuai penerimanya. Channel ini hanya untuk pengiriman; respons sukses berarti provider menerima permintaan, bukan bukti pesan dibaca.

Atur endpoint HTTPS publik tetap, method GET/POST/PUT/PATCH, encoding JSON/form-urlencoded/multipart dan autentikasi None/API key/Bearer/Basic atau custom. Parameter GET dibentuk dari payload. Header tambahan memakai objek JSON; Content-Type diatur otomatis sesuai encoding. Secret disimpan terenkripsi pada field kredensial, bukan URL, dan tidak ditampilkan kembali pada daftar.

Payload wajib memuat recipient dan message. Contoh email dengan format HTML:
```json
{
  "to": "{{recipient}}",
  "subject": "{{message.subject}}",
  "html": "{{message}}"
}
```
Untuk telepon, gunakan nomor berkode negara dan format teks. Nama field di sisi kiri mengikuti API provider. Parameter lainnya tersedia di UI.

Test ke penerima yang Anda kendalikan. Default sukses HTTP 200; pilih 201/202 jika provider memakainya. Aktifkan setelah test sesuai. Edit konfigurasi membatalkan status teruji/aktif dan memerlukan test ulang. Log menampilkan waktu, status, kode respons, referensi provider bila tersedia, dan error yang disamarkan.

Ini berbeda dari API Data Source yang mengambil data dokumen dan event webhook yang mengirim peristiwa workflow. OTP tetap memakai channel platform tepercaya.

## Memantau
Gunakan **Delivery logs** untuk status, retry dan error yang disamarkan. Periksa alamat, izin provider, template dan kuota bila gagal. Jangan mengirim ulang secara manual tanpa mengecek deduplikasi.
