## Pengaturan pribadi
Buka menu profil di top bar, lalu **Settings**. Periksa nama dan identitas akun. Ganti password dengan memenuhi verifikasi dan aturan form; perubahan password tidak dikerjakan melalui komentar atau pesan dukungan.

## Verifikasi login
Pada implementasi lokal terbaru, **Settings → Account security** menampilkan metode login Anda. Email OTP aktif secara default untuk akun internal. Setelah password benar, masukkan kode dari email terdaftar sebelum mengakses workspace. Kode berlaku lima menit; pengiriman ulang memiliki jeda dan percobaan dibatasi.

Untuk memakai authenticator, login ulang jika sesi sudah melewati lima menit, pilih **Set up authenticator**, verifikasi password jika akun memilikinya, lalu pindai QR. Simpan sepuluh recovery code secara pribadi dan konfirmasikan dengan kode authenticator. Email OTP tetap berlaku sampai konfirmasi berhasil. Aktivasi mencabut sesi lama; login berikutnya memakai TOTP atau satu recovery code. Email OTP tidak menjadi pilihan cadangan selama TOTP aktif.

Untuk kembali ke Email OTP, pilih **Switch to Email OTP**, masukkan password jika diperlukan dan kode authenticator terbaru atau recovery code yang belum dipakai. Pergantian mencabut authenticator, recovery code dan semua sesi; login kembali dengan OTP email. Pemulihan MFA oleh Owner dan transfer kepemilikan masih belum tersedia dalam increment ini.

<Note>Alur ini telah diuji di server lokal dan browser desktop/mobile. Migrasi database lama, kesiapan SMTP autentikasi operator dan penerapan produksi masih harus diselesaikan. Kanal OTP login terpisah dari kanal notifikasi organisasi.</Note>

## Pengaturan organisasi
Owner membuka bagian **Organization** pada Settings. Isi nama organisasi, domain email yang sah, logo dan warna tema. Preview logo/warna sebelum menyimpan. Domain email digunakan untuk klasifikasi penerima internal/eksternal; label internal bukan bukti kewenangan hukum.

Logo organisasi ditampilkan pada konteks organisasi yang sesuai, termasuk login tenant jika dikonfigurasi. Subdomain salah atau organisasi tidak ditemukan tidak boleh dipakai untuk memasukkan data organisasi lain.

## Anggota dan kewenangan
Gunakan bagian **User management / Members** sesuai role. Undang email yang benar, pilih role seperlunya, dan tetapkan izin kategori atau form. Tinjau masa berlaku dan status aktif. Jangan memberikan Owner hanya untuk membuat seseorang dapat Approve; beri kewenangan kategori yang tepat.

## API key workspace
Owner dapat membuka **Settings → API Access**. Buat aplikasi integrasi, pilih mapped requester, kategori/workflow/template yang boleh diakses, scope minimum dan masa berlaku key. Salin key sekali ke secret manager server Anda. Rotasi atau cabut key jika bocor. Jangan menaruhnya pada form, frontend, URL atau source repo.

API manajemen masih sandbox dan menggunakan data workspace sesuai allowlist; sandbox bukan isolasi data otomatis. Jangan menggunakannya untuk transaksi pelanggan produksi sampai aktivasi dan cakupan komersial benar-benar tersedia.

## Checklist sebelum operasi
Pastikan organisasi, anggota, izin kategori, kanal email teruji, form/workflow published, serta pengganti approver sesuai kebijakan. Lihat [kanal notifikasi](/guides/notification-channels).
