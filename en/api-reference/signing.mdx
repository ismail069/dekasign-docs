---
title: "Preview and send signing packages"
description: "Receipts bind templates, values, recipients, and expiry."
---
Design a template in the platform and allow it for the app. API keys cannot supply recipient consent.

## Preview
For a template using API Data Source, first call `POST /api/v1/signature-packages/data-fetch` with `packages:create`:

```json
{"template_id":"template-id","parameters":{"project_id":"PRJ-001"}}
```

Parameter names follow the template and may be empty or contain multiple inputs (maximum 20). The response includes supported variables and a secret `lookup_token`, bound to the issuing key and valid for 10 minutes. Include that token in the Preview body. Do not supply provider credentials here; the server uses its saved connection. Fetch creates no package or invitation. Production requires supported data-source capability and current paid authority.

`POST /api/v1/signature-packages/preview` requires `packages:create`.

```json
{
  "template_id":"template-id",
  "expires_in_days":3,
  "sender_values":{"employee_name":"Example employee","employee_number":"EMP-001"},
  "signers":[{"slot_id":"slot-id","name":"Example recipient","email":"recipient@example.com","phone":"+6281234567890","recipient_kind":"external"}]
}
```

Expiry is mandatory, 1–365 days. Match the designed slots, with 1–20 recipients. External recipients require valid email/phone. Test only destinations you control.

The response includes `preview_token`, version, and `prepared_pdf`. `pdf_url_is_source:true` means `pdf_url` points to the source, not the populated preview.

## Review, then send
POST `/signature-packages/preview/document` with `template_id` and `preview_token` for the populated PDF. Show the sender the PDF, values, recipients, and expiry. The context-bound receipt is valid for 10 minutes.

After sender confirmation, `POST /signature-packages` with `packages:create`, an idempotency key, and:

```json
{"template_id":"template-id","preview_token":"receipt-from-preview","confirmed":true}
```

Send uses the frozen preview, not another REST fetch. Changes require a new preview. `201` and `invitation_status:"queued"` mean queued delivery, not delivered email or completed consent.

## Status and archive
`GET /api/v1/signature-packages/{id}/document` with `packages:read` downloads the PDF for a **COMPLETED** package in the app/requester's private scope. Before completion, the server returns `409 FINAL_DOCUMENT_NOT_READY`. Access and version are rechecked before serving bytes; this is not a public link.

`GET /signature-packages` supports `q`, `status`, `archived=only`, and pagination. Details use `GET /signature-packages/{id}`. Both require `packages:read`.

`POST /signature-packages/{id}/archive` requires `packages:archive`, a 5–500-character reason, and an idempotency key. Packages must be terminal; active packages return `PACKAGE_NOT_CLOSED`. Evidence is retained.

The `internal_dekasign` profile is not a PSrE certificate or trusted timestamp.
