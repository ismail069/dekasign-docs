## Routing principles
Email is required for approvals and Document Sign. Use DekaSign email or your organization's channel; WhatsApp is an add-on. For the organization default, DekaSign is the fallback when custom email sending fails or a delivery failure becomes known to the system. Not all bounces can be detected. Accepted is not delivered/read.

An explicit **custom email** Actor override disables DekaSign email, including that Actor's fallback. OTP/security messages continue to use the trusted platform channel. If you need the organization-default fallback, understand the consequences before applying an Actor override.

## Add SMTP
The Owner opens **Notification channels**, selects **Add channel / SMTP**, names it, and enters:

| Field | Non-secret example |
|---|---|
| SMTP_HOST | smtp.example.com |
| SMTP_PORT | 465 or 587 |
| SMTP_SECURE | true for 465; false with mandatory STARTTLS for 587 |
| SMTP_USER | notifications@example.com |
| SMTP_PASSWORD | Enter the secret in the settings form, never documentation |
| SMTP_FROM_NAME | Organization name |
| SMTP_FROM_EMAIL | notifications@example.com |

Save, select **Test connection**, inspect the result, then activate. The SMTP test checks the connection without sending a message. Configuration changes clear tested/active status. Port 25, disabled TLS, and private hosts are not supported.

## Connect WhatsApp without JSON

As Owner, open **Management → Notification channels → Add channel**, then choose **Wati**, **Convia**, or **Bird**. Prepare your provider account and WhatsApp-approved templates first.

<Steps>
  <Step title="Enter the connection">
    Name your channel and enter the API key. Wati also requires its connected sender number with country code, digits only, such as `6281234567890`. Convia offers an optional Sender ID. Bird uses a workspace API key starting with `bk_`, not a `bm_` master key; workspace-owned templates require a sender number with `+`, such as `+6281234567890`.
  </Step>
  <Step title="Test and get templates">
    Click **Test & get templates**. DekaSign checks API access and retrieves the provider's template list. If it is empty, create and approve a template with the provider first, then retry. Search templates by name or language.
  </Step>
  <Step title="Select and review details">
    Select an **APPROVED** template. DekaSign retrieves that template's details and shows a message illustration, header, body, footer, buttons, and required parameter count. Unsupported components show an explanation and prevent saving.
  </Step>
  <Step title="Save the verified channel">
    Click **Save verified channel** after list and detail verification succeeds. The saved channel is active. Your API key is encrypted and never displayed again. When editing, leave the API key blank to keep it or enter a replacement, then test again.
  </Step>
</Steps>

<Note>
**Test & get templates** only reads the catalog and details. HTTP 200 verifies API access; it sends no message and does not prove delivery or reading. Your provider sets its own fees, quotas, and template approval rules.
</Note>

WatZap does not currently offer guided template setup in DekaSign. Its provider screen explains this limitation. Use **Custom API** when the provider documents the API you need. Existing channels remain available; review them before using them in new designs.

## WhatsApp parameters and media

On the canvas, select the **Notification** element, choose **Phone number** as recipient type, then select your WhatsApp channel. Choose a template and fill each required parameter using **Enter a value** or **Workflow parameter**. Controls follow the selected template; you do not write a JSON payload.

| Template component | Value to provide |
|---|---|
| Header/body placeholder | Fixed text or a workflow parameter value. |
| Image, video, or document header | A public HTTPS URL for the matching media type. |
| Dynamic URL button | The value replacing the dynamic part of the provider-approved URL. |
| Static footer/button | Preserved from the provider template design. |

Your provider must be able to read media URLs without a DekaSign login. Do not use private DekaSign document URLs, private network URLs, or credentials in a URL. Choose media you are authorized to share. Private files are not automatically made public. WhatsApp recipients need a registered or mapped organization phone number.

If a template changes, select it again and review parameter mappings before **Publish**. Carousel, Flow, authentication, and other unsupported components cannot be forced into a plain-text template.

## Email content on the canvas

Select **Email** and a delivery channel in the **Notification** element. Choose your content source:

- **DekaSign default**: use the built-in message design.
- **Message Template**: select a published template version available to the workflow category.
- **Manual**: enter a subject and message in **Plain text** or **HTML** mode.

Use the offered parameters and inspect **Preview**. HTML is still checked for safety; scripts are not supported. Content selection does not change the recipient or document access permissions. See [Approval Workflow Engine](/en/guides/approval-workflows) and [Email Studio](/en/guides/email-studio).

## Custom API: Email or Phone number
Open **Management → Notification channels** as Owner. Choose **Email** or **Phone number** so the canvas Notification element offers channels matching its recipient type. Channels are outbound only; success means provider acceptance, not proof of reading.

Configure a fixed public HTTPS endpoint, GET/POST/PUT/PATCH method, JSON/form-urlencoded/multipart encoding, and None/API key/Bearer/Basic or custom authentication. GET parameters come from the payload. Additional headers use JSON; Content-Type is generated for the encoding. Credentials are encrypted, kept out of URLs, and never returned in channel lists.

Recipient and message are mandatory. Example email with HTML message format:
```json
{
  "to": "{{recipient}}",
  "subject": "{{message.subject}}",
  "html": "{{message}}"
}
```
Phone channels use country-code numbers and text messages. Provider field names on the left follow its API documentation. Additional parameters are offered in the UI.

Test a recipient you control. HTTP 200 is the default; select 201/202 when required. Activate after a matching test. Editing configuration resets verification/activation and requires another test. Logs show timestamps, status, response code, provider reference where available, and sanitized errors.

This differs from document API Data Source lookups and workflow event webhooks. OTP continues through trusted platform channels.

## Monitor deliveries
Use **Delivery logs** to inspect status, retries, and redacted errors. Check destinations, provider permissions, templates, and quotas on failure. Check deduplication before manually resending.
