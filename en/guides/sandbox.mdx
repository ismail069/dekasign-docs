## Start a simulation
Open Workflow Canvas and choose **Run sandbox**. Check the active workflow name and version. Select a simulated requester and enter values matching field keys and types; **Load sample values** provides a starting point.

Choose **Start New Run**. Simulations do not submit real requests, sign Production PDFs, send real messages, or consume Production Credits.

## Read Execution Trace
Trace includes node/element/step names, IDs, events, and timestamps so you can match it to the design. Scroll within the trace panel. Return to the canvas for the workflow being tested; search its ID to select, highlight, and focus the step.

## Test decisions and conditions
At an active Actor, choose the simulated identity and decision. Enter a reason before **Request Revision** or **Reject**. Related validation messages appear within the action area.

Test each Rule output and optional Operation Task Condition using your own business scenarios. Include boundary values, unmatched conditions, invalid managers, and unavailable staff. Example values are not built-in business policies.

## Time, revision, and Operation Task
Use virtual time for Wait, SLA, and reminders. For revisions, change simulated data and Resubmit; check the return destination and revision limit. For Operation Task, inspect category, all/specific staff, singleton assignment, and simulated outcome.

Virtual time does not prove real provider delivery or scheduled worker execution. After changing the design, repeat relevant Validate and simulation checks before Publish. Report issues with the version, step ID, inputs, expected result, and actual result.
