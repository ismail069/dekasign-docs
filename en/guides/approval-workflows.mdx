Owner/Admin opens **Create Design → Workflow Engines**, creates a workflow from a Form Builder form, selects its category and opens the editor. The left panel contains elements; right-side Properties configures the selected element.

## Canvas and tracing
Use Zoom, Fit view, Focus node, Pan, Undo/Redo and the step list. Drag node headers to arrange the layout; connectors determine routing. Properties shows the **Node/Step ID**. Search an ID to highlight and focus that node and correlate it with execution traces and logs.

## Workflow elements
| Element | Purpose |
|---|---|
| Start | Begin with the selected form and version. |
| Actor | Approval by a named member or the requester’s Direct Manager; configure SLA, revision and delegation. |
| External Actor | A scoped external approval assignment with invitation, verification and authorized data. |
| Rule | Choose a route using typed parameters and AND/OR conditions. |
| Parallel Split / Join | Run branches with supported ALL/ANY rules; verify branches and joining in Sandbox. |
| Wait | Wait according to the configured duration. |
| Notification | Send using tested channels, distinguishing email from phone recipients. |
| HTTP Request | Call an API with supported configuration, mappings and outcomes; HTTP success need not mean business completion. |
| Revision / Loop | Bounded correction/repetition with an explicit return target. |
| Finish | Final approval outcome: Approved or Rejected. |
| Operation Task | Follow-up after approval and required signing; category Team Queue visibility or automatic assignment. |

## Assignment and conditions
Direct Manager resolves the **requester’s** manager, including an Owner requester. A missing/inactive/unauthorized manager blocks submission; configure [Organization Hierarchy](/en/guides/organization-hierarchy) and permissions.

Optional Operation Task Conditions choose All Staff or one/multiple Specific Staff. The category follows the workflow. See [Operation Task](/en/guides/operation-tasks).

## Save, Publish and Logging
Save stores a draft, Validate checks configuration/connections, and Sandbox uses test data with node name/ID traces. Publish creates a version for new submissions. Then create/publish a [Request Form Template](/en/guides/request-form-templates).

Choose **Logging** on the workflow list and filter by Request ID, requester or date/time. Results show status and Form UI/API source. Open a Request ID to inspect its journey and problematic step. Running requests retain their workflow version; editing the design does not rewrite history.
